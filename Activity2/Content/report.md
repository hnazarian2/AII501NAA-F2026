# Activity 2 — Part 1: Connect Four MCTS Experimental Report

## Objective

Evaluate how a Connect Four move generator using Monte Carlo Tree Search responds to changes in its selection utility weight, iteration count, expansion width, and search-tree height.

## Implementation and algorithm

The game is a 6-row × 7-column gravity board with two players (1 and 2) and columns numbered 0–6. Legal moves are non-full columns; the win detector checks four consecutive pieces horizontally, vertically and diagonally. The move generator uses MCTS with four stages:

1. **Selection:** At a fully expanded tree node, choose a child by a UCT-style score: `(1-w) × stored average playout reward + w × board heuristic + c × sqrt(log(parent_visits+1)/child_visits)`. Stored reward is from the root player’s viewpoint and inverted at the opponent’s turn. Unvisited nodes have priority. The heuristic measures open four-cell windows and centre occupancy.
2. **Expansion:** Add up to `expansion_nodes` new sibling children when an expandable node has untried moves; choose one newly added child to simulate from.
3. **Simulation:** From the selected node, choose random legal columns until the game is over, even if the tree has reached the specified `max_depth`.
4. **Backpropagation:** Update all nodes along the selected path with win = 1, loss = 0, draw = 0.5 for the root player. Repeat for the selected number of `cycles`, then recommend the root child with the most visits (with specified tie-break rules).

## Experimental method

The starting board is constructed by six moves: player 1 column 3, player 2 column 2, player 1 column 3, player 2 column 2, player 1 column 4, player 2 column 4. Player 1 moves next. The base parameter configuration is 120 cycles, two expansion nodes, tree depth 5, utility objective weight 0.25, exploration constant approximately 1.414. For each parameter, only that parameter is varied while the others stay fixed. Every setting is run with seeds 0, 1, and 2. Seeds make the experiment repeatable, but produce distinct random playout sequences. All 36 individual observations are stored in `controlled_results.csv` and generated by `connect4/controlled_experiments.py`.

## Analysis and reflection

**Does it always generate the same move?** No. Across these recorded runs, some sets of three seeds choose different columns, while other sets choose identical columns. The number of distinct columns in the results table shows this variation directly. Reusing the same board, settings, and seed produces the same output in this implementation.

**What causes differences?** Randomly ordered expansions, random tie-breaks and random playout decisions affect visit counts and empirical rewards. With finite cycles, sampling noise can change which root branch earns the highest visit count.

**What causes similarities?** Some configurations repeatedly choose the same branch because its estimated value or visit count is comparatively strong under the tested settings; fixed seeds also reproduce exactly the same random sequence for a given run. Repeated agreement is not proof of optimality.

**Effects of parameter changes:** The table provides controlled comparisons for cycles, nodes per expansion, tree depth and heuristic weight; inspect the listed columns against the base setting to see if changing each one affects recommendations. A larger budget permits more simulation evidence, whereas a wider expansion or greater depth changes search structure. A larger objective weight increases emphasis on a rule-based score. None of these changes is guaranteed to improve win rate.

## Limitations and conclusion

Three seeds per configuration and one starting board are only a small experiment. The measured data demonstrate variability or stability of *recommended columns*, not playing strength or a proven best configuration. A stronger evaluation would use several tactical board positions, more seeds, and actual win rates against consistent opponents, while recording runtime and uncertainty. In this experiment MCTS generated legal move recommendations, and the chosen move was not necessarily invariant to random seed or search settings.
